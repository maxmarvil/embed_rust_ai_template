# 0004 — Локальная сборка и отладка на Host, без Docker

Дата: 2026-10-19

## Статус

Принято (заменяет Docker-подход ADR-0002 и ADR-0003, удалённых вместе с `docker/`).

## Контекст

Первоначальная концепция строилась на Docker: сборка в контейнере, SWD-отладка с Host-зависимостью (Linux — probe-rs в контейнере, macOS — probe-rs на Host из-за ограничений Docker Desktop на USB-проброс). На практике это давало: двойную границу «Host/контейнер», разную логику отладки по ОС, лишний слой абстракции для ai-агентов и требование поддерживать образ.

## Решение

Сборка и отладка выполняются **локально на Host** (Linux и macOS), Docker исключается из Базы полностью:

- зависимости ставятся при старте работ единым скриптом `setup.sh` с автоопределением ОС (ADR-0004);
- probe-rs и GDB работают на Host напрямую на обеих ОС — граница «у кого отладчик» исчезает;
- базовые конфигурации памяти микроконтроллеров живут в `targets/` (ADR-0005).

`setup.sh` ставит: Rust через rustup + embedded-таргеты (`thumbv6m/thumbv7m/thumbv7em`, `riscv32imac`), probe-rs (прямой бинарник с fallback на `cargo install`), GDB (`gdb-multiarch` через apt на Linux / `gdb` через Homebrew на macOS), udev-правила probe-rs на Linux. Для ESP32 — отдельный сценарий `--esp32` (espup + espflash). Скрипт идемпотентен.

**Рассмотренные альтернативы**: сохранить Docker для Linux и локальную сборку для macOS — отклонено, как двойной путь с разной семантикой отладки; контейнерная сборка ради воспроизводимости — отклонена, так как rustup + lock-файлы дают достаточную воспроизводимость, а цена (образ, проброс USB) — нет.

**Consequence**: окружение Host становится частью ответственности разработчика/агента (setup при старте работ, `README.md` описывает запуск для Mac и Linux); воспроизводимость обеспечивается lock-файлами проекта, а не образом; обновление инструментов — повторным запуском `setup.sh`. Ушедшие ADR-0002/0003 описывали Docker-механику и удалены вместе с ней; их нумерация не переиспользуется.
