# 0001 — Специализация таргетов через merge Target-веток в main проекта

Шаблон предназначен для получения «чистого специализированного» проекта, а не мульти-таргетного репозитория. Поэтому каждой Target (семейству чипов, «схожих архитектурно и периферийно») соответствует одна ветка шаблона — Target-ветка. Специализация выполняется одноразово: Target-ветка подливается в main существующего проекта, после чего проект становится независимым форком Базы.

Повторная подгрузка шаблона в действующий проект не предполагается: обновления Базы (docker, toolchain, skills, агенты) проект принимает только вручную. Target-ветки между собой не мержатся; для специфических devboard допустима отдельная Target-ветка. Для специфической платы (Board) новая ветка не создаётся — плата является заботой проекта.

**Рассмотренные альтернативы**: директории таргетов в одном репозитории (`targets/stm32f4xx/`) и cargo feature-флаги — отклонены, так как обе оставляют мульти-таргетное состояние и не дают независимости проекта после старта.

**Consequence**: после Специализации дрейф Базы не синхронизируется автоматически — разница между шаблоном и проектом растёт со временем; это осознанный компромисс ради чистоты итогового проекта.
